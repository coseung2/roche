# Performance Baseline — 2026-08-18

Phase 0A framework-independent core의 최초 baseline입니다.

## 환경

- OS: Windows development workstation
- Rust: 1.95.0
- Build: `--release`
- Command: `cargo run --release --bin perf_poc`

## 표준 workload 결과

```text
workload: messages=100000 tool_events=100000 sessions=1000 build_ms=22
conversation_window: materialized=80 total=100000
tool_window: materialized=80 total=100000
session_window: materialized=50 total=1000
streaming_tail: appends=100000 max_materialized=60 scan_ms=0
terminal: ingested_bytes=52428831 resident_lines=500 resident_bytes=45000 ingest_ms=21
```

## 해석

- Conversation은 100,000건 중 viewport 40 + 양방향 overscan 20 기준 최대 80건만 materialize합니다.
- Tool event도 동일 조건에서 80건만 materialize합니다.
- Sidebar는 1,000 sessions 중 viewport 30 + overscan 10 기준 50건만 materialize합니다.
- 100,000회 streaming tail 계산에서도 materialized 범위는 최대 60건입니다.
- 50 MiB terminal stream을 처리한 뒤 UI resident history는 최근 500줄, synthetic workload 기준 45,000 bytes입니다.

`build_ms`, `scan_ms`, `ingest_ms`는 이 머신에서의 참고값입니다. CI에서는 시간 기반 임계값을 사용하지 않고 materialization / resident-data invariant를 검증합니다.

## 다음 비교점

Phase 0B에서는 같은 workload를 각 UI framework prototype에 연결하고 다음을 추가 측정합니다.

- frame time / dropped frames
- scroll latency
- jump-to-bottom latency
- process RSS / GPU memory 추세
- Markdown parse/cache 비용
- code highlighting 비용
- Windows IME와 text selection 동작
